## High-level view

The off-GNOME `ubuntu-white` gap is closed. A NOTE now fires after the desktop `case` in `step_install` whenever `ubuntu-white` is selected and the desktop isn't `gnome`, so the previously silent no-op is now visible in the install log and matches the NOTE idiom the other three components already use. The guard is correctly placed after the `case` block, so it fires for `mate`/`vanilla` without shadowing the in-`case` gnome overlay logic.

The argv value flags are hardened. `--desktop`, `--enable`, and `--disable` each check `[ -n "${2:-}" ]` and exit 1 with a specific ERROR before `shift 2`. This matters under the script's `set -e`: a value-less trailing flag would previously have consumed an unset `$2`. The `=`-form variants (`--desktop=...`) don't need the guard since they carry their own operand.

JWSTF staying OFF by default is a deliberate, documented interpretation of "make components selectable," recorded in the `DEFAULT_COMPONENTS` comment, the `COMPONENT_DEFAULTS` array, and the `(default OFF)` line in `--help`. The security regression this could have caused is not present because the ClamAV/UFW baseline JWSTF used to pull in is now the default-ON `security` component.

The `step_disk` `eval $DIALOG` idiom was left unchanged. It is pre-existing on the base branch, outside the selectable-components scope, and its input is internally constructed rather than user-derived, so deferring it does not introduce risk in this branch.

### ubuntu-white off-GNOME is now auditable

The v1 blocker was that ticking `ubuntu-white` with a `mate` or `vanilla` desktop discarded the selection with no log line, while every other component logged a NOTE on a skip. The fix adds, immediately after the `case "$INSTALL_DESKTOP"` block:

```
if component_selected "ubuntu-white" && [ "$INSTALL_DESKTOP" != "gnome" ]; then
    echo "  NOTE: ubuntu-white theme requires the gnome desktop — skipping overlay for '$INSTALL_DESKTOP'" >> "$LOG"
fi
```

Placement is correct: the gnome branch still applies the overlay inside the `case`, and this guard only fires on the non-gnome desktops, so there's no double-handling. The decision to skip rather than force the GNOME theme onto MATE/vanilla is defensible — the overlay is a GNOME theme/icon set — and the skip is now visible to anyone reading the install log.

### argv operand guards under set -e

The three value-consuming flags now validate their operand before `shift 2`:

```
--desktop)
    [ -n "${2:-}" ] || { echo "ERROR: --desktop requires a value (mate|gnome|vanilla)" >&2; exit 1; }
    INSTALL_DESKTOP="$2"; shift 2 ;;
```

`--enable` and `--disable` follow the same shape with list-appropriate messages. Errors go to stderr with a nonzero exit, matching the unknown-flag branch. The `--desktop=*`/`--enable=*`/`--disable=*` forms are untouched and correct — their operand is embedded in `$1`. This closes the v1 robustness gap; the fix is complete across all three flags.
