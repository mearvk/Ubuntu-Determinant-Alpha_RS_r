git-messages(1)
===============

NAME
----
git-messages - Inspect the message catalog and .gitmessages configuration

SYNOPSIS
--------
[synopsis]
git messages [--config <file>] [path | validate | list | rules]

DESCRIPTION
-----------
`git messages` is a read-only inspector for the Ubuntu Determinant message
system. It reports the human-facing stdout/stderr text the Edition Git would
emit and the concern classes those messages describe, using the same native
loader the binary itself uses — so what it shows is exactly what would be
applied at runtime.

The catalog starts from a set of compiled-in defaults and may be overlaid by a
per-repository `.gitmessages` file: `[MESSAGE <id>]` blocks re-word or re-stream
individual messages, and `[MAP]` lines map an intercepted output (by source
file, function, or text) to one of those messages. The configuration is
resolved from `$GIT_MESSAGES_CONFIG` if set, otherwise `.gitmessages` in the
current directory, otherwise the compiled defaults.

The command is advisory and never changes any repository state. An override
that would hide a diagnostic (an error or fatal message routed to stdout, or an
emptied message) is rejected: `validate` reports it and the compiled defaults
remain in effect. See the `MESSAGES.md` metadoc for the full model.

COMMANDS
--------
`path`::
	Print which configuration file is in effect, or note that the compiled
	defaults are being used.

`validate`::
	Load and validate the configuration. Reports whether it is usable and,
	when some overrides were unsafe and had to be ignored, warns and exits
	non-zero so the condition is not silent.

`list`::
	Print the resolved message catalog: each message's id, output stream,
	severity, and text.

`rules`::
	Print the resolved `[MAP]` rules that map intercepted output to catalog
	messages.

With no command, `list` is assumed.

OPTIONS
-------
`--config <file>`::
	Inspect a specific `.gitmessages` file instead of the auto-resolved one.
