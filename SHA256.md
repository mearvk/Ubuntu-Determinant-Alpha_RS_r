# SHA-256 — Content Integrity and Build Provenance

**Project role:** byte-level integrity checking.

SHA-256 is a cryptographic hash function that maps arbitrary input to a 256-bit digest. This project can use it to record exactly which source archives, files, or generated artifacts were observed during an initial crawl or build.

## Safety design

- Generate manifests after a source acquisition has completed and passed structural checks.
- Compare later files against the recorded digest before compilation or packaging.
- Keep manifests associated with a specific upstream version/commit and acquisition date.
- Prefer independently obtained trusted checksums or signed release metadata when upstream provides them.

## Limitations

A SHA-256 hash **does not establish that the original file was trustworthy**. It proves only that the compared bytes match the bytes represented by that digest. If an attacker controls both the file and the checksum, hashing provides no authenticity.

SHA-256 also does not inspect source behavior, malicious build instructions, compromised dependencies, or vulnerabilities in the software being built. Collision resistance is not the same thing as provenance or code review.

## OS integration policy

Use SHA-256 as one layer in a chain: trusted upstream provenance/signatures where available, Git commit identity, source-tree validation, SHA-256 manifests, unprivileged compilation, and controlled staging. Never treat a matching hash as permission to execute or install arbitrary content.
